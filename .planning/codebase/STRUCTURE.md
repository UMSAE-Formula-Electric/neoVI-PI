## Directory Purposes

**`src/`:**
- Purpose: Hardware interfacing and CAN data capture/transmission
- Contains: Python scripts for logging, playback, and post-processing
- Key files:
  - `new_logger.py`: Multi-threaded logger using python-ics SDK (primary entry point for data collection)
  - `neoVI_logger.py`: Alternative logger using vspyx SDK, outputs VSB buffer format
  - `neoVI_sender.py`: Test utility to transmit hardcoded CAN messages
  - `references.py`: Analysis tool to read VSB buffers and print decoded signals

**`can-dashboard/`:**
- Purpose: Real-time web-based visualization of live CAN signals
- Contains: Node.js server, HTML/CSS/JS dashboard, test simulator
- Key files:
  - `server.js`: Accepts JSON-streamed signals on stdin, broadcasts via WebSocket
  - `dashboard.html`: Single-page app with channel tabs, signal toggles, search
  - `simulate.js`: Generates fake CAN data for testing dashboard without hardware

**`ECU database breakdown/`:**
- Purpose: Reference documentation for vehicle electrical architecture
- Contains: Human-readable explanations of CAN messages and signals
- Generated from: DBC file, possibly team notes
- Usage: Understand message IDs, signal names, and units

**`.planning/codebase/`:**
- Purpose: Codebase analysis documents (generated by GSD tools)
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, etc.
- Generated by: `/gsd-map-codebase` command

**`.github/`:**
- Purpose: GitHub-specific configuration
- Contains: Workflow definitions, issue templates
- Committed: Yes

**`.vscode/`:**
- Purpose: VS Code editor settings (indentation, formatting, debugging)
- Contains: JSON configuration files
- Committed: Possibly (if team-wide settings); check `.gitignore`

## Key File Locations

**Entry Points:**

- `src/new_logger.py`: Main logger using python-ics. Run with `python src/new_logger.py --channels HSCAN --out logs/`
- `src/neoVI_logger.py`: Alternative logger using vspyx. Run with `python src/neoVI_logger.py --channels HSCAN`
- `can-dashboard/server.js`: Web server. Run with `python src/new_logger.py --channels HSCAN | node can-dashboard/server.js`

**Configuration:**

- `epbr2026_DBC_v1.0.dbc`: CAN message database. Loaded by loggers to decode frames. Default location: project root.
- `src/new_logger.py` (lines 41–59): Channel name ↔ NetworkID mapping (hardcoded)
- `can-dashboard/server.js` (line 20): PORT from environment or default 3000

**Core Logic:**

- `src/new_logger.py` (lines 164–211): Capture thread — polls hardware, queues raw frames
- `src/new_logger.py` (lines 214–268): Writer thread — decodes, writes CSV/JSON
- `src/new_logger.py` (lines 145–161): Transmit thread — sends test CAN messages
- `can-dashboard/server.js` (lines 66–100): Main loop — reads stdin, updates state, broadcasts WebSocket
- `can-dashboard/dashboard.html`: Browser logic handles WebSocket, DOM updates, filtering

**Testing:**

- `can-dashboard/simulate.js`: Synthetic signal generator. Run with `node can-dashboard/simulate.js | node can-dashboard/server.js` to test dashboard without hardware.
- `src/neoVI_logger.py` (line 12): `TESTING_MODE` flag to use VSB buffer instead of live hardware

**Output:**

- `logs/` directory (created at runtime): Timestamped CSV files from `new_logger.py` (e.g., `log_2026-07-30_14-23-45.csv`)
- Stdout: JSON-streamed signals (piped to Node.js server)

## Naming Conventions

**Files:**

- **Python scripts:** lowercase_with_underscores.py (e.g., `new_logger.py`, `neoVI_sender.py`)
- **Node.js scripts:** lowercase_with_underscores.js (e.g., `server.js`, `simulate.js`)
- **HTML:** lowercase.html (e.g., `dashboard.html`)
- **Config:** UPPERCASE.dbc for DBC files; lowercase.json for package manifests
- **Logs:** `log_YYYY-MM-DD_HH-MM-SS.csv` (timestamped, human-readable)

**Directories:**

- **Package code:** lowercase (e.g., `src/`, `can-dashboard/`)
- **Documentation/reference:** Mixed case (e.g., `ECU database breakdown/`)
- **Generated/temporary:** lowercase (e.g., `logs/`, `.planning/`)

**Functions:**

- **Python:** `snake_case()` (e.g., `capture_thread()`, `emit_signal()`)
- **JavaScript:** `camelCase()` (e.g., `broadcast()`, `parseFallback()`)

**Variables:**

- **Python:** `snake_case` for module/class vars (e.g., `frame_queue`, `db`, `TESTING_MODE`)
- **JavaScript:** `camelCase` for locals (e.g., `msgId`, `state`); UPPERCASE for constants (e.g., `PORT`)

**Types/Classes:**

- **Python:** PascalCase (e.g., `ThreadEvent`, `SpyMessage`) — mostly SDK types, not custom
- **JavaScript:** No explicit types; objects used structurally (e.g., `{ type, channel, id, signal, value }`)

## Where to Add New Code

**New CAN Logger (Python):**
- Primary code: `src/new_logger_variant.py` — copy structure from `new_logger.py` (capture/writer/main pattern)
- Tests: `src/test_new_logger_variant.py` (if tests are added)
- Config: Add channel mappings to `CHANNEL_MAP` dict (line 41)
- DBC: Reference existing `epbr2026_DBC_v1.0.dbc` or provide `--dbc` path

**New Dashboard Feature (Web):**
- UI updates: `can-dashboard/dashboard.html` — add HTML elements and CSS classes
- Logic: Inline `<script>` tag in dashboard.html or extract to separate `.js` file (not currently done)
- Server changes: `can-dashboard/server.js` — if new message types or state structure needed

**New Signal Decoder/Post-Processor:**
- Implementation: `src/post_processor.py` — read CSV from logger output, apply transformations
- Usage: Pipe logger → post-processor → server
- Example: Smooth noisy signals, synchronize multi-bus messages, compute derived values

**Utility Scripts:**
- Location: `src/` directory
- Naming: `<purpose>.py` (e.g., `can_monitor.py`, `database_validator.py`)
- No subpackages currently; keep flat for CLI accessibility

**Documentation:**
- Overview: `README.md` (project root)
- Dashboard usage: `can-dashboard/README.md`
- Architecture: `.planning/codebase/ARCHITECTURE.md` (generated)
- Reference: `ECU database breakdown/` (manual documentation)

**Configuration:**
- DBC database: Keep in project root, referenced by `--dbc` CLI arg (default `epbr2026_DBC_v1.0.dbc`)
- Channel mappings: Hardcoded in `src/new_logger.py` lines 41–59 (CHANNEL_MAP, NET_ID_TO_NAME)
- Environment: PORT for server (line 20 in server.js), no `.env` file currently used
- CLI args: Each script defines own `argparse.ArgumentParser` (Python) or `process.env` (Node.js)

## Typical Workflows

**Collect CAN data to CSV:**
```bash
python src/new_logger.py --channels HSCAN HSCAN2 --out logs/ --duration 60
```
Output: `logs/log_2026-07-30_HH-MM-SS.csv`

**Collect + view live in dashboard:**
```bash
# Terminal 1: start server
node can-dashboard/server.js

# Terminal 2: start logger, pipe to server
python src/new_logger.py --channels HSCAN | node can-dashboard/server.js
```
Open browser to printed URL (e.g., `http://192.168.1.42:3000`)

**Test dashboard without hardware:**
```bash
node can-dashboard/simulate.js | node can-dashboard/server.js
```
Open `http://localhost:3000`

**Post-process recorded buffer (VSB):**
```bash
python src/references.py epbr2026_DBC_v1.0.dbc logs/recording.vsb \
  --mapping "DW CAN 01" "HSCAN Discovery Channel" \
  --signal "EngineControl" "RPM"
```

**Transmit test messages:**
```bash
python src/neoVI_sender.py --hardware_sn "icsneo **1" --channels HSCAN
```
Runs until Ctrl+C; sends hardcoded test frame 0x123.
