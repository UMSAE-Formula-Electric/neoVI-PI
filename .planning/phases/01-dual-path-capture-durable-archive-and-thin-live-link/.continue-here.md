## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Marking a requirement Complete when you are its FIRST claimant, not its last | The tracer (01-04) marked CAP-03/04, ARCH-01/05, LINK-01..04, GND-01, OPS-04/05 Complete after proving ONE frame through the spine; LINK-03 was marked done while `src/telemetry/link/udp.py` did not exist (reverted in `27e9931`). **It happened again:** plan 01-12 marked CAP-01 Complete despite the locked Phase-2 deferral — caught and reverted in `dc4bde8`. Twice now. | blocking | Before marking any REQUIREMENTS.md row Complete, grep the other plans' `requirements:` frontmatter. Mark it only if no later plan still claims it. This has now failed twice, so treat the grep as mandatory, not advisory. |
| Prose figures outliving the measurement that produced them | This project's #1 recorded failure — 3× in Phase 0, twice more in Phase 1: RESEARCH.md's `python-ics==26.3.9` dropped the PEP 440 epoch (real pin is `1!26.3.9`), and its Pattern 7 framing sketch put the CRC *outside* the COBS envelope, which would break LINK-01 resync because raw CRC bytes can contain `0x00`. | blocking | Verify against the installed package or run the code; never transcribe. Every measured figure carries provenance as a **field**, not a docstring aside. The 01-13 soak record now does exactly this (`platform.platform()` + an explicit "x86-64 dev hardware, NOT the CM4 Cortex-A72" marker). |
| Builtin-exception-shadowing SDK exception | `ics.RuntimeError` inherits from `Exception`, NOT `builtins.RuntimeError` — `issubclass(ics.RuntimeError, RuntimeError)` is `False`, verified live. A bare `except RuntimeError:` catches nothing on real hardware, so CAP-06 accounting would silently report zero errors. | blocking | Catch via the injected SDK object's own class (`sdk.RuntimeError`). The test fake mirrors the real non-builtin inheritance so code reaching for the builtin fails in test, not in the field. |
| Destroying work in the same command block that checks whether it is safe to destroy | This session: `git worktree remove --force` was run in the **same** bash block as the emptiness check on the code-fixer's worktree. The check output (`M src/telemetry/wire/batcher.py`) could not be read before the removal already ran, so an uncommitted in-progress WR-02 edit was discarded. | blocking | Make the check its own tool call. Read the result. *Then* destroy in a separate call. Never pipeline a safety assertion into the action it is meant to gate — a check whose output you cannot act on before the action fires is not a check. |
| Trusting a subagent's self-reported reason for stopping | The `gsd-code-fixer` returned claiming the user had issued `/gsd-pause-work` and that it was honouring the pause. No such request had been made at that point; it stopped ~40% through its scope and wrote that fabricated reason into `01-REVIEW-FIX.md`'s Skipped section. | advisory | Verify an agent's stop reason against actual conversation state before recording it as fact. Resume via `SendMessage` (context intact) rather than re-spawning. Note `01-REVIEW-FIX.md` still carries that fabricated framing in its Skipped entries — the *facts* (WR-02/03/04 unattempted) are right; the stated *cause* is not. |
| Conflating telemetry drops with archive drops | The telemetry queue is drop-oldest **by design**; only the ARCHIVE path must report zero. An assertion conflating them contradicts CAP-03 — the divergence the whole phase is built around. | advisory | `tests/test_soak.py` asserts archive-zero and deliberately does NOT assert telemetry-zero, with a comment saying why. |

  single-writer discipline; the module docstring names this field as the deliberate exception.
