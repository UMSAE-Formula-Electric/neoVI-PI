<objective>
Make CAP-03, CAP-04, CAP-05, and CAP-06 provable properties of the fan-out rather than
intentions — and prove CAP-01's architectural half: one implementation carrying both buses in
one stream.

Purpose: the fan-out is the single structural mechanism that keeps the live path from ever
endangering the archive. `01-CONTEXT.md`'s locked decision makes it two independent queues
with deliberately divergent overflow policies precisely so the telemetry consumer holds no
handle that could apply backpressure. `01-PATTERNS.md` also flags the exact debt this plan
must not inherit: `src/new_logger.py` swallows errors through a debug helper invisible unless
a module flag is set, and drops unknown channels with a warning while continuing as though
nothing happened.

Output: counters that are exact under sustained overflow, errors that carry frame context,
and a structural guarantee backed by a test rather than by a comment.
</objective>

Written in `tests/test_fanout.py`, replacing 01-02's placeholder skip. Queue depths in these
tests are small explicit test values, never the shipped config's, so the assertions stay
readable and a config tune cannot change what they mean.

`test_discard_counting` — the node `01-VALIDATION.md` names for CAP-05:
- with a telemetry deque of depth four and twenty allowlisted frames submitted without any
  consumer draining, the discard count is exactly sixteen
- the deque holds exactly the last four frames submitted, in order — the policy is
  drop-oldest, so what survives is the freshest data, not the first data
- with fewer frames submitted than the deque's depth, the discard count is zero
- a frame not on the allowlist never reaches the telemetry deque, and filtering it out is not
  counted as a discard — a filtered frame and a dropped frame are different events and must
  not share a counter

Archive never drops (CAP-03):
- submitting exactly the archive queue's capacity leaves every frame retrievable in order,
  with no discards recorded on the archive side
- submitting one frame beyond capacity sets the stop event, sets the archive-overflow flag,
  emits a critical log record naming the frame's channel, id, and timestamp, and does not
  silently continue accepting further frames as though nothing happened

Structural non-blocking (CAP-04):
- a telemetry consumer that never drains at all does not change how many frames reach the
  archive queue, nor the producer's per-submit call time, across a burst several times the
  telemetry depth
- `submit` never raises `queue.Full` out to the caller and never blocks: assert it completes
  for every frame in a burst that overflows the telemetry side many times over
- a module-level assertion that `telemetry.capture.fanout` does not import anything from
  `telemetry.archive` or `telemetry.link` — the producer holds queues and nothing else, and
  that one-directional dependency is what makes the guarantee structural

High-water marks:
- both high-water marks equal the deepest occupancy actually reached, and neither decreases
  when the queues later drain
  </behavior>
  <action>
Extend `src/telemetry/capture/fanout.py`. Keep the tracer's `submit` shape and both overflow
policies exactly as they are — they were verified end to end and are the locked decision — and
add the accounting that makes them observable.

Make `FanOutCounters` carry, at minimum: frames submitted, frames enqueued for archive,
archive high-water mark, telemetry high-water mark, telemetry frames enqueued, telemetry
frames discarded by overflow, telemetry frames filtered out by the allowlist, and the
archive-overflow flag. Keep the filtered count and the discarded count as separate fields —
conflating them would make the live path's discard rate unreadable, and it is the number the
pit engineer will be looking at when the link looks unhealthy.

Keep the pre-append fullness check exactly as the tracer wrote it. A `deque` with a `maxlen`
gives no signal at all that it evicted an item, so the discard count must be derived from
whether the deque was already at `maxlen` immediately before the append. There is no
after-the-fact inspection that recovers this.

Update high-water marks with a plain `max` against the current occupancy on every submit.
Single-item `deque.append` and `Queue.put_nowait` are each individually safe under the GIL,
and the counters object is written only by the capture thread and read after join, so no lock
is needed — say so in the docstring rather than leaving a reader to wonder.

On archive overflow, emit the critical log record before setting the stop event, so the log
reaches a handler even if the shutdown path is what runs next. Include the channel, frame id,
and timestamp of the frame that could not be enqueued.
  </action>

  — that clause is deliberately deferred to Phase 2 by user decision — and it does not
  substitute for the hardware-attached dual-bus check `01-VALIDATION.md` lists as manual-only

Error context (CAP-06):
- a frame whose id is absent from the ID dictionary is counted as a telemetry-path encode
  error and logged at warning severity or higher with its channel, id, and timestamp; the
  archive path still receives it, because the archive is not dictionary-bound and must not
  lose a frame just because the live path cannot encode it
- an over-length payload is counted and logged the same way, and does not propagate an
  unhandled exception out of `submit`
- the first occurrence per frame id is logged in full and repeats are counted without
  re-logging, so a persistently unknown id cannot flood the log at bus rate and hide
  everything else
- assert on captured log records with pytest's `caplog`, not on stdout, and assert the record
  carries the frame context rather than only that some message was emitted
  </behavior>
  <action>
Add the CAP-06 error accounting to `src/telemetry/capture/fanout.py`. Every failure the
fan-out can encounter — an id the dictionary does not know, a payload over the CAN maximum,
an unexpected exception from the telemetry side — is caught by its specific named type, given
a counter field on `FanOutCounters`, and logged with the offending frame's channel, id, and
timestamp attached.

Rate-limit the logging per frame id: log the first occurrence at full detail, then increment
a counter without re-logging. At bus rate a single persistently-unknown id would otherwise
emit thousands of identical records per second and bury everything else, which is the same
visibility failure as swallowing the error, arrived at from the other direction. Report the
suppressed totals on the counters object so nothing is actually lost.

A telemetry-side failure must never cost the archive a frame. Order `submit` so the archive
enqueue happens first and unconditionally, and wrap only the telemetry side in the error
handling — a frame the live path cannot encode still belongs in the archive, because the
archive is the durability guarantee and is not dictionary-bound.

Explicitly do not reproduce `src/new_logger.py`'s two flagged anti-patterns: no bare
`except Exception` that reports through a debug helper and then exits, and no unresolvable
input accepted with a warning while the code carries on as though the input were valid.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Denial of Service | Bounded archive queue | high | mitigate | Fixed-capacity queue with a fatal-on-full policy: the session stops loudly with the offending frame's context rather than growing memory until the process is killed. An unbounded queue would only relocate the failure. |
| T-01-18 | Denial of Service | Log flooding by a persistently unknown frame id | medium | mitigate | Per-frame-id log rate limiting: first occurrence logged in full, repeats counted without re-logging and reported on the counters object, so a bus-rate error stream cannot bury every other diagnostic. |
| T-01-19 | Tampering | An unknown or malformed frame taking the archive path down with the telemetry path | high | mitigate | The archive enqueue happens first and unconditionally; only the telemetry side is inside the error handling, so a frame the live path cannot encode is still archived. The durability guarantee never depends on the encodability of a frame. |
| T-01-20 | Repudiation | Silently discarded telemetry frames | medium | mitigate | Overflow discards are counted exactly via the pre-append fullness check, and allowlist filtering is counted separately, so the live path's loss rate is an observable number rather than an inference. |
