<objective>
Build the typed, fail-closed loader for `config/logger.json` — the single place channels, the
DBC path, archive cadence, telemetry queue sizing, link settings, and the twelve-message
critical-channel allowlist are declared (OPS-05).

Purpose: `00-DECISION.md` § What later phases should build against is explicit that subset
membership must be "a data-driven allowlist Phase 1 reads at startup, not a set baked into
code" — changing which messages stream live is meant to cost a config edit and a restart of
both ends. `01-CONTEXT.md` extends the same principle to the channel/net-ID map, which
`src/new_logger.py` currently hardcodes. This plan builds that file and the loader that
refuses to guess about it.

Output: one config idiom for the project, not two — `src/telemetry/measure/config.py`'s exact
shape, applied to the runtime logger.
</objective>

  <action>
Create `config/logger.json` at the repository root — deliberately NOT beside
`.planning/phases/00-compression-ratio-gate/config/gate.json`. `gate.json` is a phase
artifact recording modelling assumptions; `logger.json` is runtime configuration the car
reads at every boot, and `01-CONTEXT.md` fixes its default path as `config/logger.json`.
Note this divergence in the module docstring so a later reader does not "fix" it.

Give the file exactly these top-level keys:

- `schema_version` — integer, 1
- `dbc_path` — string, `epbr2026_DBC_v1.0.dbc`, resolved relative to the repository root
- `channels` — list of objects, each with `name` (the friendly label carried into the archive
  and used as the MCAP channel topic), `netid` (the symbolic `ics` constant name as a
  string), and `bus` (the logical bus label). Ship two entries matching the neoVI PI's two
  vehicle buses, following `src/new_logger.py`'s existing `NET_ID_TO_NAME` labels: MAIN on
  `NETID_HSCAN`, SENSOR on `NETID_HSCAN2`.
- `capture` — object with `poll_interval_s` (0.01, matching `new_logger.py`'s existing poll
  cadence) and `hardware_serial` (JSON null, meaning take the first device found)
- `archive` — object with `root_dir` (`sessions`), `queue_depth` (50000),
  `flush_every_records` (1000), `flush_every_s` (0.25), `done_marker_filename` (`.done`).
  The two flush values are the starting cadence `01-CONTEXT.md` locked; both live in config
  precisely so they can be tuned without a code change.
- `telemetry` — object with `queue_depth` (1000), `batch_frames` (100, matching
  `00-REPORT.json`'s `meta.batch_frames` so Phase 1's live path and Phase 0's measurement
  describe the same batch size), `batch_max_age_s` (0.05), and `allowlist`.
  The batch age bound is not a free choice: `wire/encoder.py`'s CFR delta-t field is a
  uint16 in microseconds, so `MAX_DELTA_T_US` caps how long a single batch can span before
  `BatchWindowExceeded` is raised. Validate `batch_max_age_s` as positive AND strictly below
  `MAX_DELTA_T_US` divided by one million, importing that constant from `wire/encoder.py`
  rather than restating the number, and name both the configured value and the derived
  ceiling in the error message. The shipped 0.05 leaves clear margin under that ceiling while
  keeping live latency well inside the project's sub-second requirement.
- `link` — object with `kind` (`loopback`) and a `udp` sub-object always present regardless
  of `kind`, holding `local_host`, `local_port`, `remote_host`, `remote_port`,
  `recv_bufsize`. Default the UDP block to a localhost pair. Size `recv_bufsize` generously
  at 8192 rather than tightly to the largest batch: `01-RESEARCH.md` Pattern 6 records that
  `socket.recvfrom` silently truncates an oversized datagram, which would masquerade as link
  corruption in the LINK-02 counters.

Populate `telemetry.allowlist` with the twelve message names from `00-DECISION.md`
§ Critical channels, in that document's order: M176_Fast_Info, M192_Command_Message,
M166_Current_Info, M167_Voltage_Info, CAN_WHEEL_SPEED, BRAKE_TEMPS,
M195_Pedal_Press_Percent, Battery_Volt_1_Overall_Param_Std, CAN_VEHICLE_SPEED,
HTL_CH_ID_SAFETY_LOOP_STATUS, HTL_CH_ID_BRAKE_PRESSED, M160_Temperature_Set_1. Names, not
frame IDs — names are what a team member editing this file can reason about, and the loader
resolves them against the DBC so a typo is caught at startup rather than silently narrowing
the live stream.

Create `src/telemetry/logger/__init__.py` (empty package marker) and
`src/telemetry/logger/config.py`, copying `src/telemetry/measure/config.py`'s structure
element for element:

- a module docstring that states the refusal-to-guess philosophy up front
- module-level `REQUIRED_*_KEYS` frozen sets, one per block, diffed in BOTH directions so
  unknown keys and missing keys each raise separately and each name the offending key
- one exception class, `LoggerConfigError`, with the same one-line "validates rather than
  defaults" docstring shape as `GateConfigError`
- frozen dataclasses per block — `ChannelConfig`, `CaptureConfig`, `ArchiveConfig`,
  `TelemetryConfig`, `UdpConfig`, `LinkConfig` — plus the top-level `LoggerConfig` holding a
  `raw: dict = field(default_factory=dict, repr=False, compare=False)`
- `LoggerConfig.default_path()` classmethod resolving `Path(__file__).resolve().parents[3] /
  "config" / "logger.json"`, never a hardcoded absolute path
- `LoggerConfig.config_hash` property: SHA-256 over the canonicalised raw JSON
  (`sort_keys=True, separators=(",", ":")`), truncated to 12 hex characters, so a session's
  archive can record which config produced it
- shared free-function validators `_require_positive_number`, `_require_positive_int`,
  `_require_non_empty_str`, `_require_port`, each raising with the dotted key path
- per-block `_parse_*` free functions that type-check the block, diff its keys, validate each
  field, and return the frozen dataclass
- `load_logger_config(path) -> LoggerConfig` wrapping the open in `try/except OSError` and
  the parse in `try/except json.JSONDecodeError`, each re-raised as `LoggerConfigError`
  `from exc`

Path handling (V12 file-and-resource control): resolve `dbc_path` and `archive.root_dir`
relative to the repository root rather than the process working directory, so the logger
behaves identically whether launched from the repo root or from a systemd unit in Phase 3.
Confirm `dbc_path` exists during load and raise `LoggerConfigError` naming the resolved path
if it does not. Do not require `archive.root_dir` to exist — the session layer creates it.

Keep the loader free of any `cantools` or `ics` import: put allowlist resolution in a
separate free function `resolve_allowlist(config, db) -> frozenset[tuple[int, bool]]` in the
same module, which builds a name-to-key map from `db.messages` and raises `LoggerConfigError`
naming every unresolvable allowlist entry at once rather than only the first. This keeps
config loading fast, importable without hardware, and independently testable.

Deliberately drop the anti-pattern `01-PATTERNS.md` flags at `src/new_logger.py`'s
`resolve_net_ids` line 131: an unrecognised channel there only emits a warning and keeps
running with no filtering. Here, a `netid` string that does not look like an `ics` constant
name is a hard `LoggerConfigError` at load, and 01-09 makes an unresolvable one a hard error
at device-open time.

Finally add a session-scoped `logger_config` fixture to `tests/conftest.py`, mirroring the
existing `gate_config` fixture exactly — same scope, same one-paragraph docstring explaining
that it is the single source of truth a test uses rather than duplicating literals.
