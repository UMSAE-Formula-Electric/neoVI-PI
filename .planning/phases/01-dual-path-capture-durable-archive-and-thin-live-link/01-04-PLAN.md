Wire ONE frame through every layer. One call site per layer, no batching of concerns, no
second entry point, real error handling on the single path. Where `01-RESEARCH.md` supplies
a verified reference implementation, copy it rather than re-deriving it — Patterns 2, 3, 6,
and 7 were executed against the installed libraries in the research session, not read from
documentation.

Before writing the archive writer, print the real `mcap` signatures and code against what
prints, not against memory: run a one-liner that imports `mcap.writer.Writer` and prints
`inspect.signature` for `__init__`, `start`, `register_schema`, `register_channel`,
`add_message`, and `finish`. `01-RESEARCH.md` verified only the `use_chunking` flag,
`add_message`, and `finish` behaviour empirically; the schema and channel registration
signatures are NOT covered by that verification and must not be assumed. This project's
recorded history is three separate cases of prose figures disagreeing with measured reality
— do not add a fourth.

One convention that applies to every module in this plan: use the standard library `logging`
module with a module-level `logging.getLogger(__name__)`, never a hand-rolled print helper.
`src/new_logger.py`'s `log`/`debug` pair routes to stderr through bare prints and hides
everything behind a module flag, which is precisely the visibility problem CAP-06 exists to
fix. Stdlib logging defaults to stderr, so the existing convention that stdout carries only
machine-readable output is preserved. Entry-point modules configure handlers; library modules
never do.

Build, in this order:

**1. `framing/errors.py`** — one base exception `FramingError` with subclasses
`CobsDecodeFailed`, `CrcMismatch`, and `BatchFormatError`, following the
`CfrError`/`BatchWindowExceeded`/`PayloadTooLong` family shape in `wire/encoder.py`: a
one-line docstring per class saying exactly when it is raised. The deframer catches the base
type to count-and-continue; tests catch the specific subclass to discriminate.

**2. `framing/crc16.py`** — `crc16(data: bytes) -> int` over CRC-16/CCITT-FALSE via
`crccheck.crc.Crc16CcittFalse.calc`, plus `pack_crc(value) -> bytes` using `struct` format
`"<H"` and `verify_crc(payload: bytes, trailer: bytes) -> None` raising `CrcMismatch` naming
both the computed and received values. `01-RESEARCH.md` Pattern 6 records that `crccheck`
resolves `Crc16CcittFalse.__name__` to `Crc16Ibm3740` — the same registered parameters under
two names, not a different algorithm. No requirement mandates a CRC-16 variant; this is a
discretion call and the choice belongs in the module docstring.

**3. `framing/cobs_frame.py`** — `frame(payload: bytes) -> bytes` returning
`cobs.encode(payload + pack_crc(crc16(payload)))` followed by a single `0x00` delimiter
byte, and `unframe(frame_bytes: bytes) -> bytes` doing the inverse and raising
`CobsDecodeFailed` (wrapping `cobs.cobs.DecodeError`) or `CrcMismatch`.

Note in the docstring that this deliberately deviates from `01-RESEARCH.md` Pattern 7's
sketch, which computes COBS over the payload and leaves the CRC outside the COBS envelope.
That ordering breaks LINK-01's stated resync property: raw CRC bytes can contain `0x00`, so a
delimiter-scanning receiver would split a valid frame in half. Putting the CRC inside the
COBS envelope guarantees the only zero byte in the stream is the delimiter, which is exactly
what "resynchronizes at the next frame delimiter" requires. Record this correction in the
SUMMARY.

**4. `wire/batcher.py`** — the batch container. Header is `struct` format `"<BBQHB"`,
13 bytes: protocol_version, dict_version, base_timestamp_us, frame_count, batch_seq — the
same four fields and the same total that `wire/overhead.py`'s `BATCH_HEADER_BYTES` already
documents. Assert at module import that the struct's `.size` equals
`overhead.BATCH_HEADER_BYTES`, so the analytic model and the real layout cannot silently
diverge. Provide `pack_batch(dict_version, base_timestamp_us, batch_seq, records) -> bytes`
and `split_batch(payload) -> tuple[BatchHeader, list[bytes]]`, the latter raising
`BatchFormatError` on truncation, a length that overruns the buffer, or a frame_count that
disagrees with the number of records recovered.

CFR records are variable-length and their length is not derivable from the CFR header alone,
so each record inside a batch carries a one-byte length prefix. State plainly in the module
docstring that this costs one byte per frame beyond what Phase 0's D-06 overhead model
assumed, and that it is a batch-layout choice this phase owns — the CFR byte layout itself
(D-05) is untouched, and `wire/encoder.py` is imported unchanged. Compute the actual cost
using `wire/overhead.py`'s own functions against the twelve-message subset and record the
recomputed subset bit rate in the SUMMARY as a measured figure, not an estimate. Raise
`BatchFormatError` if any record exceeds 255 bytes or the batch exceeds 65535 records.

**5. `link/base.py`** — a `typing.Protocol` named `Link` with exactly the three methods
`01-CONTEXT.md` locked: `send(data: bytes) -> None`, `recv(timeout: Optional[float] = None)
-> Optional[bytes]`, `close() -> None`, each with a `...` body. Minimal surface, same style
as `wire/frame_source.py`'s `FrameSource`. No asyncio.

**6. `link/loopback.py`** — `LoopbackLink` wrapping a `queue.Queue`, per `01-RESEARCH.md`
Pattern 7's verified reference. `recv` returns `None` on timeout rather than raising.

**7. `archive/record.py`** — the archive's per-message payload layout, shared by the writer,
the recovery reader (01-05), and the replay source (01-12) so it is defined exactly once.
`struct` format `"<IB"`: frame_id as uint32, then a flags byte whose bit 0 marks an extended
ID; the CAN payload follows and its DLC is implied by the remaining length. Provide
`pack_frame(frame: RawFrame) -> bytes` and `unpack_frame(data: bytes, log_time_ns: int) ->
RawFrame`. The archive stores raw frames, never CFR bytes — CFR carries per-ID delta state
that is fragile to loss and is a wire format, not an archive of record.

**8. `archive/writer.py`** — `ArchiveWriter`, built directly on `01-RESEARCH.md` Pattern 2's
verified reference. Three facts that must survive into the code, each verified empirically in
the research session:
- open the file yourself and hold the file object; never hand `mcap` a string path, because
  you need the file descriptor to fsync
- construct `Writer(file_obj, use_chunking=False)` so every `add_message` reaches the stream
  immediately. The library default buffers up to 1 MB of messages in process memory before
  anything is written at all, which at raw-CAN record sizes is tens of thousands of frames —
  strictly worse than an unflushed OS buffer, and incompatible with the locked
  record-count-or-time cadence, which `mcap`'s own `chunk_size` knob cannot express because
  it is a byte threshold
- `mcap.writer.Writer` never calls `flush` or `fsync` anywhere in the class, so the cadence
  is entirely this module's job: after each `add`, flush the file object and call
  `getattr(os, "fdatasync", os.fsync)` on its file descriptor when either
  `flush_every_records` or `flush_every_s` has elapsed, whichever comes first. The `getattr`
  fallback is required for the code to run at all on the Windows dev box, where
  `os.fdatasync` does not exist — the Linux branch the CM4 actually uses is not exercisable
  here, and that limit belongs in the docstring.

Register one MCAP schema and one channel per configured channel name, topic
`/can/{channel_name}`; `log_time` is the frame timestamp in nanoseconds. `close()` calls
`Writer.finish()` (the only call that writes DataEnd, the summary, the footer, and the
trailing magic bytes), then flushes and fsyncs, then closes the file.

**9. `archive/session.py`** — `SessionPaths` (directory, mcap path, done path, session name,
and which naming source produced it) plus `new_session(root_dir)` and `mark_done(session)`.
For the tracer, name the session from UTC as `YYYYMMDD-HHMMSS` and record the naming source
as the UTC branch; 01-05 adds the monotonic-counter fallback for a CM4 booting with no RTC
battery. Each session gets its own directory under the archive root — that is OPS-04's
"discrete sessions rather than one unbounded file" and it is what makes an interrupted
session identifiable afterward.

`mark_done(session, writer)` implements `01-RESEARCH.md` Pattern 3's ordering exactly. Take
the writer as a required argument and raise if its `is_closed` property is not yet true —
that makes ARCH-05's "only after close-and-flush returns" a structural precondition rather
than a calling convention someone can forget. Then write the marker file, flush it, fsync its
own descriptor, then fsync the containing directory. Guard the directory fsync behind a
`sys.platform` check — the research session verified it raises `PermissionError` on Windows —
so the ordering logic itself stays exercisable on the dev laptop even though the syscall is
Linux-only. Never write the marker optimistically. `ArchiveWriter` therefore exposes an
`is_closed` property set only after `finish()`, the final flush, and the final fsync have all
returned.

**10. `capture/fanout.py`** — the architectural centre. Define `CapturedFrame` as a
`NamedTuple` of `channel: str` and `frame: RawFrame`, so a frame carries its bus without
modifying the frozen `RawFrame` contract. Define a mutable `FanOutCounters` dataclass holding
archive high-water mark, telemetry high-water mark, telemetry discard count, and an
archive-overflow flag.

`FanOut(archive_maxsize, telemetry_maxsize, telemetry_allowlist, stop_event)` holds a
`queue.Queue(maxsize=...)` for the archive and a `collections.deque(maxlen=...)` for
telemetry, per `01-RESEARCH.md` Pattern 1's verified shape. `submit(captured)` does exactly
two things and neither can block:
- `put_nowait` onto the archive queue; on `queue.Full`, log at critical severity that the
  durability guarantee is at risk, set the overflow flag, set the stop event, and return.
  A full archive queue is fatal by locked decision — the archive consumer never drops, so
  silently discarding is not an option and an unbounded queue would only relocate the failure
  to an OOM kill.
- if and only if the frame's `(frame_id, is_extended)` key is in the telemetry allowlist,
  check whether the deque is already at `maxlen` BEFORE appending, then append. `deque` with
  a `maxlen` gives no signal that it evicted anything, so the discard count must be computed
  from that pre-append fullness check, never by inspecting the deque afterward.

The allowlist filter lives here, upstream of the encoder, because filtering before encoding
saves CPU and queue pressure as well as bandwidth rather than paying to encode frames that
are then thrown away.

**11. `ground/deframe.py`** — `Deframer(dictionary, options=None)` with a `feed(data: bytes)`
generator that accumulates bytes, splits on the `0x00` delimiter, and for each complete
segment unframes, splits the batch, and CFR-decodes each record, yielding a list of
`RawFrame` per successfully recovered batch. A byte-stream interface rather than a
datagram interface is what lets the same deframer serve UDP now and a serial port in Phase 9
with no change above it.

Catch `FramingError` and `wire.decoder.DecodeError` per segment, increment the matching
counter on a `DeframeCounters` dataclass (batches OK, COBS failures, CRC failures, batch
format failures, records decoded, record decode failures), and continue to the next segment.
A corrupt batch is discarded and counted, never passed upstream and never allowed to
terminate the loop. Cap the accumulation buffer at a configured maximum frame size and, on
exceeding it, discard the pending bytes and count the event — an unterminated stream must not
grow memory without bound.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TB-1: link → ground station | Bytes arriving on the link are untrusted: they may be truncated, corrupted, adversarially malformed, or absent |
| TB-2: filesystem → archive readers | An MCAP file may be truncated at an arbitrary byte by a power cut |
| TB-4: CAN bus → capture | Hardware frames are unvalidated input; a frame whose ID is not in the dictionary or whose payload is over-length must not crash the pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Denial of Service | `ground/deframe.py` `Deframer.feed` | high | mitigate | Every layer of the deframe chain raises a specific caught exception type — `CobsDecodeFailed`, `CrcMismatch`, `BatchFormatError`, `DecodeError` — each counted and skipped per segment. No unhandled exception can reach and kill the consumer loop. Proven in this plan's test by flipping a byte in a framed batch. |
| T-01-05 | Denial of Service | `Deframer` accumulation buffer | high | mitigate | The pending-bytes buffer is capped at a configured maximum frame size; a stream that never presents a delimiter discards its pending bytes and increments a counter instead of growing memory without bound. |
| T-01-07 | Denial of Service | `FanOut` archive queue | medium | mitigate | Bounded `queue.Queue`; a full queue sets the stop event and halts the session loudly rather than growing until the OOM killer intervenes. |
| T-01-12 | Tampering | `wire/decoder.py` invoked on link bytes | high | mitigate | The CFR decoder already raises named `DecodeError` on every malformed or under-length buffer and on a delta record with no stored baseline; the deframer catches it per record and counts it. No decoded value derived from a failed record is ever emitted. |
| T-01-04 | Information Disclosure | Unauthenticated link payload | low | accept | Loopback in this plan has no exposure at all. The general case — anyone in range can receive — was already assessed as low priority for a short-range, single-team, non-actuating competition system. Re-assess if any actuation is ever placed downstream of decoded signals. |
</threat_model>
