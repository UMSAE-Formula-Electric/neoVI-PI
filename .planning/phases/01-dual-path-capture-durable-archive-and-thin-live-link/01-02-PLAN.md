  <action>
Create `requirements.txt` at the repository root as the single authoritative manifest
(OPS-06's own wording: exact pins, clean-machine installable). Use the `package==version`
format `requirements-dev.txt` already establishes. Pin exactly these eight, alphabetically:
`cantools==42.0.3`, `cobs==1.2.2`, `crccheck==1.3.1`, `lz4==4.4.5`, `mcap==1.4.0`,
`python-ics==1!26.3.9`, `pytest==9.1.1`, `zstandard==0.25.0`.

Three pinning facts to get right, each already checked against the installed interpreter
rather than taken from prose:

1. `python-ics` uses PEP 440 epoch 1 — its installed version string is `1!26.3.9` and the
   correct specifier is `python-ics==1!26.3.9`. A pin of `python-ics==26.3.9` parses fine
   but resolves to a different (epoch-0) version and will not match what is installed.
   `01-RESEARCH.md`'s illustrative install line drops the epoch; it is wrong on this point
   and this plan corrects it. Record the correction in the SUMMARY.
2. `lz4` and `zstandard` are `mcap`'s transitive dependencies and must be pinned explicitly
   even though Phase 1's writer disables chunk compression — `01-RESEARCH.md` § Standard
   Stack records that `mcap` imports them unconditionally at module load.
3. Include `pytest` in `requirements.txt`. The test suite is how every requirement in this
   phase is proven, so it is a provisioning dependency of the system, not an optional extra.

Add a header comment stating that this file is the authoritative manifest for both runtime
and test dependencies, and that `requirements-dev.txt` is the superseded Phase 0 file kept
only for that phase's provenance.

Then edit `requirements-dev.txt`: keep both existing pins byte-identical, and replace only
its header comment so it states that `requirements.txt` is now authoritative and that this
file is retained unchanged as the Phase 0 record. Do not add packages to it, and do not
convert it to a `-r requirements.txt` include — its two pins are what 01-03's
`test_requirements_pinned` cross-checks for drift against the new manifest.

In `pytest.ini`, add a `markers` section registering exactly one marker: `slow`, described
as a long-running soak or load test excluded from the quick feedback loop. Leave
`pythonpath`, `testpaths`, and `addopts` untouched.

In `.gitignore`, add rules so on-car session output never enters the repository: the
`sessions/` directory (the default `archive.root_dir` 01-03 configures) and `*.mcap`.
Place them under a comment explaining that captured session archives are run artifacts.
  </action>
