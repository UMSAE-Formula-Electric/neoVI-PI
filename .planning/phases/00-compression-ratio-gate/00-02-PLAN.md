<interface_contract>
## Byte layout — implement exactly, do not re-derive

The Compressed Frame Record (CFR) is already fully specified in `.planning/research/ARCHITECTURE.md` Pattern 3 and quoted in `00-RESEARCH.md` § "Architecture Patterns → Pattern 3". Field order, widths, and semantics:

| Offset | Field | Width | Semantics |
|---|---|---|---|
| 0 | `flags` | 1 B | bit0 = `FLAG_KEYFRAME` (0x01), bit1 = `FLAG_EXTENDED_ID` (0x02), bits 2-7 reserved and always zero |
| 1 | `id_index` | 1 B | index into the static dictionary |
| 2 | `seq` | 1 B | per-CAN-ID sequence, wraps at 256 |
| 3-4 | `delta_t_us` | 2 B | unsigned 16-bit little-endian, microseconds since the batch base timestamp |
| 5 | `trim_count` | 1 B | count of trailing zero bytes elided from the XOR delta |
| 6..N | `payload` | var | keyframe: the full DLC bytes. delta: `XOR(payload, last_payload_for_this_id)` with trailing zero bytes removed |

`struct` format for the fixed header: `"<BBBHB"` (6 bytes).

**Reconstruction rule the decoder must implement:** original DLC = `len(cfr) - 6 + trim_count`. On a keyframe, `trim_count` is 0 and the payload bytes are the frame payload verbatim. On a delta, re-append `trim_count` zero bytes to the trimmed delta and XOR against the stored last payload for that `id_index`.

**Keyframe forcing rules (encoder):** emit a keyframe when (a) this is the first frame seen for that CAN ID, or (b) the DLC differs from the stored last payload's length for that ID. Never emit a delta across a DLC change — the XOR would compare two different-length byte strings.

## Ablation switches — `EncoderOptions`

`EncoderOptions` is a frozen dataclass with four boolean fields, each changing the layout in a defined way. Both encoder and decoder take the same options instance; a mismatch is a caller error, not a wire-format negotiation (dictionary-version negotiation is Phase 4 scope).

| Field | Default | Effect when False |
|---|---|---|
| `payload_delta` | `True` | Every frame is a keyframe; `trim_count` always 0 |
| `use_dictionary` | `True` | Byte 1 is replaced by a 4-byte little-endian raw `frame_id`, growing the header to 9 bytes |
| `sequence_byte` | `True` | Byte 2 is omitted, shrinking the header by 1 byte |
| `trim_trailing_zeros` | `True` | `trim_count` is always 0 and the full-width XOR delta is written |

## Frame source contract

```
RawFrame = NamedTuple(timestamp_us: int, frame_id: int, is_extended: bool, payload: bytes)
FrameSource = Protocol with a single method  frames(self) -> Iterator[RawFrame]
```

Field order matches the raw tuple shape already used by `src/new_logger.py` lines 202-208 (timestamp first, payload last). D-08 requires that a future real-log reader can be dropped in as a second implementation with no change to the encoder or the measurement tool.
