<objective>
Make remaining NVMe space something the team acts on before a session fails, not something they
discover when a write fails: a two-stage threshold check against the archive root, refusing to start
a new session below critical, warning loudly during a run in progress, and never deleting anything.

**Marks:** none. This plan addresses OPS-03 but does NOT mark it. The OPS-03 decision requires the
figure be surfaced in THREE places — heartbeat state, startup log line, and an explicit runbook
check step — and the runbook does not exist until 03-07. 03-07 is the sole marker for OPS-03. Do not
touch `.planning/REQUIREMENTS.md` in this plan.

Purpose: success criterion 3 asks for space to be surfaced "while there is still time to act on it".
A log line alone does not achieve that for someone standing at the car, which is why the same figure
also drives the heartbeat state 03-01 already publishes.

Output: `src/telemetry/ops/disk_monitor.py` and its two wiring points in the existing logger entry
point.
</objective>

  <behavior>
    - `free_bytes` one byte below `critical_free_bytes` returns state `critical`.
    - `free_bytes` exactly equal to `critical_free_bytes` returns `warn`, not `critical` — the comparison is strictly-less-than and exactly-at-threshold resolves to the better band.
    - `free_bytes` one byte below `warn_free_bytes` (and above critical) returns `warn`.
    - `free_bytes` exactly equal to `warn_free_bytes` returns `ok`.
    - `free_bytes` far above both returns `ok`.
    - The injected `disk_usage_fn` receives the resolved measurement path and is called exactly once per check.
    - When the given path does not exist, the check measures its nearest existing ancestor directory and reports that path in the reading — it does not raise and does not create the directory.
    - A fake `disk_usage_fn` returning a tuple where `used + free` is strictly less than `total` (the real ext4 root-reserve case) produces a correct band with no error — nothing in the module derives a percentage from `total`.
  </behavior>
  <action>
Create `src/telemetry/ops/disk_monitor.py`.

    - Module constants `DISK_OK = "ok"`, `DISK_WARN = "warn"`, `DISK_CRITICAL = "critical"`.
    - `DiskReading` frozen dataclass: `measured_path: Path`, `free_bytes: int`, `total_bytes: int`,
      `state: str`.
    - `check_disk_space(path, *, warn_free_bytes, critical_free_bytes,
      disk_usage_fn=shutil.disk_usage) -> DiskReading`. Resolve `path` to its nearest existing
      ancestor before calling `disk_usage_fn` — the archive root legitimately does not exist yet at
      first boot (the session layer creates it) and measuring the filesystem it will live on does
      not require the leaf directory. Then band it: strictly below critical → `critical`; else
      strictly below warn → `warn`; else `ok`.
    - The `disk_usage_fn` default is the stdlib `shutil.disk_usage` (D: stdlib, not `psutil`, not
      shelling out). The injectable default is what keeps this unit-testable on the Windows dev box
      without touching the real filesystem, matching this project's existing seam convention.
    - Document in the module docstring, citing 03-RESEARCH.md: on Linux `shutil.disk_usage(...).free`
      is `f_bavail * f_frsize` — space available to an unprivileged user, already excluding
      root-reserved blocks — which is exactly the right number for a service running under a
      dedicated non-root user, with no adjustment. And: `total` is computed from a different block
      count than `free`, so on a real filesystem `used + free` can be less than `total`; this module
      therefore compares `free` against configured byte counts and never derives a percentage.
    - Add a short paragraph naming what this module deliberately does NOT do: it never deletes,
      rotates, or prunes anything. Auto-pruning was rejected outright in 03-CONTEXT.md as
      contradicting the project's core value that no run's data is ever lost.
    - `logger = logging.getLogger(__name__)` at module scope; no logging configuration here.

Write the behaviour assertions first with a fake `disk_usage_fn` returning `(total, used, free)`
tuples, then implement until they pass.
  </action>

  <behavior>
    - With an injected disk reading of `critical`, `main()` raises `SystemExit(1)` and no session directory is created under the archive root.
    - The same run publishes a final heartbeat whose state is `stopped-error` and whose detail names the free bytes and the critical threshold.
    - With an injected reading of `warn`, `main()` proceeds — a warn-level start is not a refusal.
    - Every start, in all three bands, emits one startup log record naming the free bytes, the measured path, and the band.
    - With the reading transitioning `ok` → `warn` mid-run, the snapshot's state becomes `degraded` and the detail names the band; the session is NOT stopped and the archive still receives its `.done` marker on a clean finish.
    - With the reading at `critical` mid-run, the state is `degraded` and the run still continues to a clean finish — a critical band mid-run never stops a session in progress.
    - The loud in-run warning is emitted on every band transition and at most once per `_DISK_WARN_LOG_INTERVAL_S` while a non-ok band persists — a 1 Hz check must not produce a 1 Hz log.
    - No test in this file, and no code path added by it, calls `unlink`, `rmtree`, or any other removal against a session directory.
  </behavior>
  <action>
Two wiring points in `src/telemetry/logger/cli.py`, both driven by `config.ops`.

**Startup gate.** In `main()`, after `config = _apply_overrides(config, args)` and after 03-01's
`booting` publish, call `check_disk_space(config.archive.root_dir,
warn_free_bytes=config.ops.disk_warn_free_bytes,
critical_free_bytes=config.ops.disk_critical_free_bytes)`. Always log one INFO record naming
`measured_path`, `free_bytes`, and `state` — this is the startup log line OPS-03's decision names as
one of its three surfaces, and it fires in the `ok` band too, not only when there is a problem.
If the band is `critical`: log at CRITICAL naming free bytes and the configured critical threshold,
`publish_now` a `stopped-error` snapshot whose `detail` carries the same two numbers, then
`raise SystemExit(1)`. This MUST sit before `_run_session`, because `_run_session` calls
`new_session()` — after that a session directory exists and "refused to start a new session" would
no longer be true (D: at critical, refuse to START a new session).

**In-run recheck.** Extend 03-01's `snapshot_fn` closure in `_run_session` — do NOT add a second
timer thread; the publisher already ticks at `heartbeat_interval_s`. Each tick re-runs
`check_disk_space` against the same archive root, puts `disk_free_bytes` and `disk_state` into the
snapshot's `extras`, and returns `state="degraded"` with a `detail` naming the band when the band is
`warn` or `critical`. The run continues in every case: a partially-written session is worth more
than no session, Phase 1's archive is crash-safe by design, and stopping a run pre-emptively loses
more than letting it continue (D: warn loudly during a run in progress, NEVER auto-delete).
Rate-limit the loud log with a module constant `_DISK_WARN_LOG_INTERVAL_S = 60.0`: emit at WARNING
(band `warn`) or CRITICAL (band `critical`) on every band transition, and thereafter at most once
per interval while the band persists. Track the last-logged band and time in the closure, using the
publisher's injected clock so the test drives it without sleeping.

`degraded` here means a concrete fault the operator can act on — disk band, `archive_overflow`, or
`archive_write_failure`. Do NOT map a zero `frames_per_s` to `degraded`: a parked car with the bus
unpowered legitimately produces no frames, and a false `degraded` in that state would train the team
to ignore the indicator. Record that reasoning in the closure's comment.

Inject the disk check into `_run_session`/`main` via an optional keyword parameter defaulting to the
real `check_disk_space` so the tests drive all three bands with a fake, following the same
injectable-callable convention as `disk_usage_fn` itself. Do not add a test-only branch inside the
production function.

Tests go in a new `tests/test_logger_cli_ops.py` and drive `main()`/`_run_session` in-process with
`--source synthetic --duration-s 1` and a `tmp_path` archive root and heartbeat path — this file
owns the ops-side CLI behaviour so `tests/test_logger_cli_smoke.py` stays a Phase 1 artifact.
  </action>
