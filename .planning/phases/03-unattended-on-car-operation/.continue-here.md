## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Premature requirement marking | A plan marks a requirement `Complete` that a later plan in the same phase also claims. Happened twice in this repo. | blocking | Fixed marking-ownership table (above) + a re-grep-and-halt instruction inside every marking task's `<action>`. |
| `configparser` for systemd unit linting | `strict=True` raises on a second `After=`; `strict=False` silently keeps only the last value. Both proven live by the researcher. A "passing" test would accept a file with half its intended targets. | blocking | `03-06` must specify a hand-rolled line-based structural checker that preserves duplicate keys as a list. `configparser` is forbidden in `tests/test_deploy_unit_file.py`. |
| `StartLimitIntervalSec` / `StartLimitBurst` in `[Service]` | Wrong section does not error — systemd logs `Unknown key ..., ignoring` and continues, so restarts are simply never rate-limited. Silently worse than a hard failure. | blocking | `03-06`'s lint asserts both keys are present in the parsed `[Unit]` section and absent from the parsed `[Service]` section. |
| Prose figures with no measurement behind them | e.g. writing an archive growth rate to justify a disk threshold. | blocking | Disk defaults (20 GiB / 5 GiB) are documented as *chosen round numbers*; no growth-rate figure is written anywhere. |
| Scope reduction language | "v1", "for now", "static placeholder", "wired later". | advisory | The remaining three plans deliver their full scope; tracer-first splitting is expansion across plans in the same phase, and each plan names which later plan completes what it starts. |

## Critical Anti-Patterns (do NOT repeat these)
