| Using `configparser` on a systemd unit file | Verified live: systemd permits duplicate keys; `strict=True` raises on a second `After=`, `strict=False` silently keeps only the last. Either makes the lint a lie. | blocking | 03-06 Task 2 is a hand-rolled line-based checker preserving duplicate keys, with a synthetic duplicate-key test and a `git grep` assertion that `configparser` appears nowhere in it. | Prose figures outliving the measurement that produced them | This project's #1 recorded failure — 5 occurrences. | blocking | Verify against the installed package or by running the code. | Destroying work in the same command block that checks whether it is safe to destroy | An uncommitted edit was once lost to `git worktree remove --force` running alongside its own authorizing check. | blocking | Check in its own tool call. Read the output. Then act separately. |
| Trusting a tool-reported completion without verifying the effect | This session: `gsd-tools query commit --files` silently skipped two staged **deletions**, committing only the modified file.   stays runnable). Phase 1 stranded on *three* hardware items; confining this to one was explicit.

  suggested `src/telemetry/ops/config.py` — that layout is a circular import, and CONTEXT.md forbids
  a second config mechanism. Flagged in 03-01's `<output>` for the SUMMARY.
- **Exactly five heartbeat states.** A clean stop is signalled by the status file's *absence*, not a
  sixth state — a stale `capturing` file would read to a human as a failure.
- **`degraded` is reserved for concrete faults** (disk warn/critical, `archive_overflow`,
  `archive_write_failure`). Zero frames/s does **not** map to degraded: a parked car with the bus
  unpowered legitimately produces no frames, and a false `degraded` trains the team to ignore it.
- **Disk policy:** refuse to START below critical, warn during a run, **never auto-delete** —
  auto-pruning would contradict "no run's data is ever lost".
</decisions_made>
