<task type="auto">
  <name>Task 1: A car stand-in that speaks the real wire</name>
  <files>src/telemetry/ground/simulate.py</files>
  <action>
Create `src/telemetry/ground/simulate.py` as a module entry point (`python -m
telemetry.ground.simulate`), following `src/telemetry/logger/cli.py`'s CLI conventions rather than
inventing new ones: the same argparse style, the same stderr logging configuration, and the same
signal-handlers-before-resources ordering with handlers that do nothing but set a stop event.

Give it a module docstring stating plainly what it is and is not: it is a car stand-in for
demonstrating and manually testing the pit dashboard with no hardware present; it is NOT a test
fixture for the car-side logger (which already has its own synthetic source flag) and it is NOT the
no-hardware proof of the full chain (that is the two-process end-to-end test).

Arguments: a config path defaulting to the shared logger config; a link-kind override; an entropy
bracket chosen from the same bracket names the car-side logger offers; a duration bound; a
real-time pacing multiplier defaulting to 1.0; a loop flag; and a log level. Reuse the existing
bracket-name constant rather than restating the names.

Wiring, all of it reusing what already exists:
- Load the logger config and the gate config with the existing typed loaders, letting their
  fail-closed errors surface as a logged message and a non-zero exit rather than a traceback.
- Load the DBC and build the id dictionary with the existing helpers.
- Build a `SyntheticFrameSource` from the DBC, the dictionary, the gate config, and the chosen
  bracket, narrowed to the config's telemetry allowlist message names, so the simulator produces
  exactly the critical-channel subset the real live path carries — not the full bus. Do not
  re-implement per-signal value generation the way the retired JavaScript simulator did; the
  synthetic source's entropy-bracket and payload-mutation model replaces it wholesale.
- Build the CAR side of the link, which is the mirror image of the ground station's documented role
  reversal: the car binds its own local address and sends to the remote address, where the ground
  station is listening. Refuse a loopback link kind with a clear message explaining that an
  in-process loopback link cannot reach a ground station in another process, and that a UDP link is
  what makes the two-terminal demo work. Fail closed rather than appearing to run and sending
  nothing.
- Build an `Encoder` over the dictionary and a `TelemetryPipeline` with the config's batch frame
  count, batch max age, and dictionary version, feeding it a `collections.deque` bounded by the
  config's telemetry queue depth — the same bounded-deque shape the capture fan-out gives it on the
  car, so the simulator inherits the same never-block behaviour rather than a different one.

The frame feed: iterate the synthetic source's frames, wrap each in a `CapturedFrame` tagged with
the first configured channel name (the same choice the car-side logger already documents for its
synthetic mode, since the synthetic source models per-message rate and entropy rather than per-bus
separation, and the channel tag never crosses the wire — the ground station derives channel from
the DBC), append it to the deque, and pace the loop in real time: sleep until the wall clock
reaches the frame's own offset from the first frame's timestamp, divided by the pacing multiplier.
Pacing is what makes this a live demo rather than an instantaneous burst that fills the dashboard
and then goes quiet. Check the stop event every iteration so the process is always promptly
killable. With the loop flag set, restart the frame iteration when it is exhausted, re-basing the
pacing clock, so a demo can run for as long as someone is watching it.

Shut down cleanly: set the stop event, join the pipeline thread with a bounded timeout, close the
link, and log a one-line summary naming frames fed, batches sent, and any counters the pipeline
already exposes.
  </action>

  <behavior>
    In-process, fast, no subprocess and no sockets — drive the simulator's frame-feeding against a
    recording stand-in link that collects everything sent, then feed those bytes to a real
    `Deframer` and decode what comes out.

    - test_simulator_output_deframes_to_allowlisted_dbc_messages: every batch the simulator sends
      survives COBS+CRC deframing with zero framing failures, and every recovered frame's id
      resolves to a DBC message whose name is in the config's telemetry allowlist. Catches: a
      simulator that emits bytes the real ground station cannot read, and one that leaks
      non-allowlisted traffic onto the live path. This is the assertion that makes the simulator
      trustworthy as a manual-test instrument — without it, a dashboard demo could look right while
      the wire was wrong.
    - test_simulator_refuses_a_link_kind_that_cannot_reach_another_process: constructing the car
      link with the in-process loopback kind raises with a message naming the problem. Catches the
      silent-no-op demo: a simulator that appears to run while nothing can ever receive it.
    - test_pacing_multiplier_bounds_a_short_run: a short run at a high pacing multiplier completes
      well inside a generous literal wall-clock bound. Catches a pacing bug that sleeps on absolute
      rather than relative timestamps, which would make the simulator appear hung.

    Not written: no test asserting the dashboard renders the simulated values. That needs a browser,
    which is not available to the automated suite; it is the human check below, stated as such
    rather than faked with a file-content assertion.
