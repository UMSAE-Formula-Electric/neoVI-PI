## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, toggle thumb inset |
| sm | 8px | Compact element spacing, `.msg-group` margin-bottom |
| md | 16px | Header/content horizontal padding, default row gaps |
| lg | 24px | (reserved — not currently used; available for any new section this phase adds) |
| xl | 32px | (reserved) |
| 2xl | 48px | (reserved) |
| 3xl | 64px | (reserved) |

Exceptions: **This is a ported file, not a redesign** (`02-CONTEXT.md`: "port `can-dashboard/dashboard.html` rather than rewriting it"). Its existing CSS predates this scale and is treated as a **frozen legacy exception zone** — do not "fix" its spacing as part of this phase. Representative inherited exceptions kept as-is: toggle track/thumb geometry (`36×20`, `28×16`, `14×14`, `10×10` circles, `2px` insets, `12px`/`16px` translateX), badge padding (`2px 7px` on `.msg-id`, `1px 6px` on `.ch-count`), signal-row left padding `50px` (aligns rows under the toggle), and card/control radii (`5px`–`10px`). If Phase 2 adds any genuinely new chrome (e.g. a staleness indicator), it must use the 4/8/16 scale above rather than inventing a new odd value.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 | 1.5 |
| Label | 12px | 400 | 1.4 |
| Heading | 15px | 600 | 1.2 |
| Signal value (display) | 14px, monospace | 600 | 1.2 |

Consolidated from the ported file's existing rules (search input/buttons/tabs/signal names at 13px; units/badges/stats/status text at 11–12px; header logo at 15px/600; `.sig-value` at 14px monospace/600). This is a distillation, not a rewrite — the pixel values in the CSS stay exactly as they are; the roles above are how the checker should read them.

Exception (inherited, not to be expanded): `.msg-name` uses `font-weight: 500` in the ported CSS, between the two declared weights. Retained as-is rather than touched, per the "port, not rewrite" lock. Any new text this phase introduces must use 400 or 600 only.

**Domain-specific hard rule:** every signal value MUST use the monospace stack with `font-weight: 600`, right-aligned, fixed `min-width`, exactly as `.sig-value` already does. This is load-bearing for the phase's "legibility of a changing number at a glance" requirement — digits must not jitter horizontally as values change several times per second. Do not remove or weaken the existing `.sig-value` rule when porting.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0d0d0f` (`--bg`) | Page background |
| Secondary (30%) | `#16161a` / `#1e1e24` (`--surface` / `--surface2`) | Header, search bar, channel-tab bar, message-group cards, stats bar |
| Accent (10%) | `#4f8ef7` (`--accent`) | Active channel-tab underline, `.msg-id` badge background/text (`--accent-dim`), per-signal toggle "on" fill, mini range-bar fill, search-input focus border, logo icon background |
| Destructive | `#e8504a` (`--red`) | Not used this phase — no destructive actions exist in this UI. Reserved token only; currently repurposed for the connection-error status dot (a status color, not a destructive-action color per this template's definition) |

Accent reserved for: active channel-tab indicator, `.msg-id` badge, per-signal toggle "on" state, the mini sparkline-style range bar (`.sig-bar`), search-input focus ring, and the header logo mark. Never used for body text, borders, or as a general highlight.

**Inherited semantic tokens beyond the 60/30/10/destructive set** (kept from the port, not introduced): `--green` (`#34c77b`) means "live" — connection status dot pulse and the per-message toggle "on" state; `--amber` (`#f0a028`) is declared but currently unused in markup (reserved, do not repurpose it for staleness — see below). `--dim` (`#55555f`) is the muted/inactive gray already used for placeholder text and the disconnected status dot.

**New this phase — staleness color:** a signal value whose `ts` is older than the staleness threshold (see Copywriting Contract) renders its `.sig-value` text in `--dim` (`#55555f`) instead of `--text` (`#e8e8ed`). This reuses an existing token rather than introducing a new color, and is deliberately **not** `--amber` or `--red` — those are reserved for link-level health states that are explicitly Phase 6 scope, and reusing them here would visually conflate "this one number stopped updating" with "the whole link is degraded," which the domain context and `02-CONTEXT.md` both say not to do yet.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None — this phase adds no new user-initiated action to the browser. It is a passive, always-connecting live view (`EventSource` auto-reconnects with no button); the existing "All on" / "All off" / "Collapse all" toolbar buttons are visibility utilities carried over unchanged, not CTAs |
| Empty state heading | "Waiting for CAN data…" (unchanged from the ported file — still accurate) |
| Empty state body | "The ground station will start streaming automatically once it's running and the link is receiving frames:<br><br>`python -m telemetry.ground.cli`<br><br>Signals will appear here as soon as data arrives — no page reload needed." Replaces the current `node server.js` instruction, which becomes false once Node is retired (GND-03). **Exact invocation is a default, not locked** — `02-CONTEXT.md` leaves the serving-mode CLI flag to planner/executor discretion; whichever flag name is chosen (e.g. `--serve`, `--dashboard`) must be substituted into this string so the empty state never tells the engineer to run a command that doesn't exist |
| Error state (connection) | Status dot turns to the existing `.error` (red) class; status text reads **"Reconnecting…"** — not "Error" — because `EventSource` retries automatically with no operator action required, and a generic "Error" would wrongly suggest something needs fixing. Keep the current on-open/on-error copy pairing (`"Live"` / `"Reconnecting…"`) exactly; only the transport underneath (`WebSocket` → `EventSource`) changes |
| Destructive confirmation | Not applicable — no destructive action exists in this phase's UI (no delete, no data-clearing control is added) |

**Additional copy element — per-signal staleness (new this phase, not in the template's default rows but required by the locked "UI greys stale entries" decision):**

| Element | Copy / Behavior |
|---------|------|
| Staleness threshold | 3000ms (3 seconds) — default, Claude's-discretion value. Rationale: fast enough that a genuinely frozen value (car has stopped sending that message, or the whole link dropped) is visibly flagged well within an engineer's glance cadence, slow enough that normal per-message cycle-time jitter (many DBC messages cycle at 100ms–1s; some far slower) never falsely flags a healthy signal. This is a flat, UI-only timer — not a per-signal expected-rate model, which is explicitly Phase 6/7 scope |
| Stale value treatment | `.sig-value` text color changes from `--text` to `--dim`; no opacity change on the row, no strikethrough, no icon. Deliberately distinct from the existing `.hidden` (manually-toggled-off) treatment, which dims the *whole row* via `opacity: 0.35` — a stale value must never look identical to a value the engineer chose to hide, per the domain constraint that a frozen number must never be mistaken for a current one, and must also never be confused with an intentionally-hidden one |
| Un-stale on update | The moment a fresh update for that signal arrives, its color reverts to `--text` and the existing `.flash` (green pulse) animation plays exactly as it does today — no special-casing needed |

## UI Considerations

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | message/signal list (list-collection) | ✅ covered | Existing `.empty` state (icon, heading, body) is retained; body copy is updated to reference the Python ground station invocation instead of `node server.js` (see Copywriting Contract) |
| loading | connection status (nav / static-content) | ✅ covered | Status text reads "Connecting…" from page load until the first SSE event arrives; the content area shows the empty state during this window — there is no separate spinner/skeleton, matching current behavior |
| error | connection status (nav) | ✅ covered | Any `EventSource` error sets the status dot to `.error` and text to "Reconnecting…"; the browser's built-in retry means no user action is ever required, matching the existing WebSocket reconnect behavior 1:1 |
| error | per-signal value (list-collection) | 🧪 backstop | New this phase: a signal whose `ts` exceeds the 3000ms staleness threshold renders dimmed (see Copywriting Contract "Stale value treatment"). No held-out visual test exists yet to pin this — verify via a snapshot/DOM assertion in the phase's test suite or manual UAT, per the honest-verifier rule (no silent pass) |
| populated | message/signal list (list-collection) | ✅ covered | GND-05: a newly connected browser's first SSE event is the full state snapshot; `rebuildAll()` renders every known channel/message/signal in one pass rather than each arriving individually — this is the locked behavior, unchanged from `server.js`'s `snapshot` semantics |
| partial | message/signal list (list-collection) | ✅ covered | A message group can render before every one of its signals has ever been seen — signal rows are added lazily on first occurrence (existing `ensureSignalRow`), which is the same incremental behavior the ported file already has; no special partial-state UI is needed |
| overflow | message list, channel tabs (list-collection, nav) | ✅ covered | Search filters the message/signal list by name or ID; channel tabs scroll horizontally (`overflow-x: auto`) when there are more channels than fit; both are existing, unchanged behavior |
| zero-one-many | channels, messages, signals (list-collection) | ✅ covered | Zero → empty state; one channel → single tab with no ambiguity; many (up to 128 messages, 2 channels) → search + collapse-all + the stats bar's live counts keep it scannable, unchanged from the ported file |
| long-text | message names, signal names (static-content) | ✅ covered | `.msg-name` and `.sig-name` already truncate with `text-overflow: ellipsis` in the ported CSS; no change needed |
